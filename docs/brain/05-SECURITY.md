# 05 — Security

Audit date: 2026-09-25. Scope: `services/api`, `apps/mobile`, `services/admin-dashboard`. Every fix below has an
automated test unless it says otherwise. The test files are `services/api/test/security.test.ts`, `env.test.ts` and
`flow.test.ts`. Total: 38 tests, all passing.

## Audit results

| # | Item | Result before | Fixed | What was found → what changed | Evidence |
|---|---|---|---|---|---|
| 1 | OTP brute-force (login + Aadhaar) | **FAIL** | Yes | The login OTP counter was read, then checked, then incremented. Parallel guesses raced past it, and the budget reset with every new OTP. The Aadhaar OTP had no limit. → Attempts are now reserved atomically (`updateMany … attempts < max`). The phone locks after 5 wrong guesses within `OTP_LOCKOUT_MINUTES` (15), counted across OTPs, and sending is blocked while locked. The Aadhaar OTP allows 5 wrong guesses (`aadhaarOtpAttempts`), then needs a new OTP. | `assertNotLockedOut()` in `auth.routes.ts`; `kyc.routes.ts`; tests "1. OTP brute-force protection" (4) |
| 2 | TEST_OTP production guard | **PARTIAL** | Yes | The old check was `NODE_ENV === 'production' && TEST_OTP`, but NODE_ENV defaulted to `development`, so a server deployed without NODE_ENV would still accept the fixed OTP. → `parseEnv()` now requires NODE_ENV to be *explicitly* `development` or `test` for TEST_OTP to be allowed. Misspelt values fail validation. | `src/config/env.ts`; `env.test.ts` (5); live: the process exited 1 both for `production + TEST_OTP` and for `TEST_OTP` without NODE_ENV or a `.env` file |
| 3 | Server-side admin role enforcement | PASS | — | `adminRouter.use(requireAuth, requireRole('admin'))` covers all 19 admin routes. `requireAuth` re-reads the role from the database on every request. | test that calls all 19 routes (anonymous → 401, affiliate → 403); demotion test |
| 4 | KYC document exposure | PASS | Hardened | There's no static serving. `/files/*` needs an HMAC signature and expiry, and URLs are only issued to the owner (`/kyc`) or an admin (`/admin/kyc/:userId`). → Request logs no longer include query strings, so signatures don't leak into logs. | `file.routes.ts`, `app.ts` (morgan `:path`); flow test checks the forged signature → 403 |
| 5 | Secrets hygiene | PASS | Hardened | The three `.env` files are ignored by git. Neither commit (`d3fe6c5`, `04a4376`) contains the real JWT secret or encryption key. Committed on purpose: the dev database credentials and the dev admin password `Admin@12345`. → The seed refuses the default or any short (< 12 characters) admin password in production. | `git grep` over all revisions; `prisma/seed.ts` (the seed guard has no automated test) |
| 6 | PAN / bank masking | PASS | — | Stored as AES-256-GCM plus a masked copy; only masked fields are ever selected into responses; the admin panel renders only the masked fields. | test "never returns raw PAN or account numbers to the admin KYC view" |
| 7 | Input validation / uploads | **PARTIAL** | Yes | The storage extension came from the client's filename, and the MIME type was trusted, so HTML could be uploaded labelled as an image. The referral code parameter wasn't validated. Amounts above ₹2.14 crore overflowed INT4 and caused a 500. → The extension now comes from the MIME type, magic bytes are checked, the display name is sanitised, and there are multipart limits and a cap of 20 documents per user. The code must be 4–16 letters or digits. Amounts are capped at ₹2 crore with a 400 error. | "7. Upload validation" tests (2); overflow test; referral code test |
| 8 | JWT expiry / re-auth | **PARTIAL** | Mostly | Every token lasted 7 days, there was no server-side logout, and the algorithm wasn't pinned. → Admin tokens last 12 hours, the algorithm is pinned to HS256, and `POST /auth/logout` bumps `tokenVersion` (signing out everywhere), wired into both apps. Refresh tokens are **not** implemented (see O2). | "8. Sessions" tests (3) |
| 9 | CORS | **PARTIAL** | Yes | The dev `.env` had `CORS_ORIGINS=*`, which became "allow any origin". → The default is now `http://localhost:5173`, and production refuses `*`. Note: auth uses bearer headers, not cookies, so CORS isn't a CSRF vector here. | `env.test.ts`; live: the admin origin got the allow header, `evil.example` got none |
| 10 | Dependency audit | **PARTIAL** | API: yes; mobile: left on purpose | **API:** 3 high and 2 moderate, all in packages my packages depend on (Prisma CLI → `deepmerge-ts` 7; firebase-admin → `uuid` 9). npm's own fix was a breaking Prisma downgrade, so patched versions are pinned instead via `overrides` → 0 vulnerabilities, and Prisma validate, generate, migrate and all tests still work. **Mobile:** 10 moderate, 0 high or critical, all in Expo build tooling (`xcode` → `uuid`); npm's only fix is downgrading to Expo SDK 46, which would break the app. **Admin panel:** 0. | `npm audit` in each package |
| 11 | Other findings | **FAIL** (6 issues) | Yes | (a) An admin could log in by phone OTP, bypassing the password → 403. (b) Percentage commissions used the affiliate-entered deal amount → the admin must confirm the amount, and the dialog isn't pre-filled. (c) `trust proxy` was hard-coded to 1, so clients could fake `X-Forwarded-For` to dodge IP limits → now `TRUST_PROXY`, default off. (d) Paid KYC provider calls had no per-user limit → 15 per hour per user. (e) Team members' phone numbers were visible at every level → masked below level 1. (f) Admin passwords could be guessed per account (only a per-IP limit existed) → 10 failed attempts per email per 15 min. Also: startup requires a JWT secret of 32+ characters, and production refuses a zero encryption key, the placeholder JWT secret and the mock KYC provider. Checked and fine: raw SQL is parameterised; ledger, earnings and leads are scoped to the caller; there's no `dangerouslySetInnerHTML`. | "11. Other findings" tests (5); admin OTP test; admin lockout test; live faked-`X-Forwarded-For` check |

## Still open (prioritised)

| ID | Priority | Issue | Action |
|---|---|---|---|
| O1 | **High, before any multi-instance deploy** | Every rate limiter (OTP, admin login, KYC provider, public endpoints) uses express-rate-limit's in-memory store. The limits apply per process and reset on restart. The OTP and Aadhaar lockouts themselves live in the database and are **not** affected. | Add a shared store (e.g. `rate-limit-redis`) and set `TRUST_PROXY` correctly for the hosting setup. |
| O2 | High | There are no refresh tokens. Affiliates re-login by OTP every 7 days, and logout revokes *all* of a user's devices (there's no per-device session list). | Add refresh tokens with rotation and a sessions table (per device, revocable); shorten access tokens to about 15 minutes. |
| O3 | High | Admin accounts have no MFA, and there's no audit log of admin actions: who approved a KYC, commission or payout isn't recorded. | Add TOTP MFA for admins, and an append-only `admin_audit_log` written by every `/admin` mutation. |
| O4 | Medium | Money columns are INT4 paise: each amount is capped at ₹2 crore, and an affiliate's lifetime balance at about ₹2.14 crore. | Migrate `*_paise` columns and `commission_rules.value` to BIGINT; handle `bigint` serialisation in the API. |
| O5 | Medium | The admin JWT is stored in `localStorage`, so any XSS in the admin panel could steal it. No Content-Security-Policy is set for the admin panel (it has no hosting yet). | When hosting it, serve it with a strict CSP. Consider an httpOnly cookie session with CSRF protection. |
| O6 | Medium | Signed document URLs work as bearer links: anyone holding one can view the file for up to 10 minutes. | Consider a shorter `SIGNED_URL_TTL_SECONDS` (e.g. 120), or an authenticated proxy download for admins. |
| O7 | Medium | `POST /leads/public` lets anyone create leads under any valid referral code, with only an IP limit (20/hour). There's no UI for it yet. | Before building the landing page, add CAPTCHA or OTP verification of the lead's phone. |
| O8 | Medium | There's no TLS locally; the mobile app talks to the API over plain HTTP on the LAN. | In production, terminate HTTPS at the proxy and use an `https://` `EXPO_PUBLIC_API_URL` in EAS builds. |
| O9 | Low | The mobile app's moderate `npm audit` findings come from Expo tooling. | Re-run the audit on every Expo SDK upgrade. Don't use `npm audit fix --force`. |
| O10 | Low | There's no key rotation for `DATA_ENCRYPTION_KEY` or `JWT_SECRET`. | Add a key id (`kid`) to the encryption format and the JWT header, and support two keys during rotation. |
| O11 | Low | There's no account deletion or data export (DPDP Act obligations). | Define a retention policy, and add delete/export endpoints that keep the ledger for its legally required period. |
| O12 | Low | The production seed guard (item 5) has no automated test. | Add a test that runs the seed with `NODE_ENV=production` and the default password, and expects it to fail. |
| O13 | Info | The real KYC, SMS and payout providers aren't integrated. When they are, keep the promises made here: never persist Aadhaar numbers, keep provider API keys out of logs, and verify webhook signatures. | A review checklist item for those PRs. |
