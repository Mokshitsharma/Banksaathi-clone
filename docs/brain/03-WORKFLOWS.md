# 03 — Screens and workflows (from the screen files)

Every button listed here was taken from the actual component source. "→" shows what the action calls or where it
navigates. Pull-to-refresh reloads the screen's data; most screens also reload whenever they gain focus
(`useFocusData` in `apps/mobile/src/hooks/useAsync.ts`).

## Mobile app (`apps/mobile`)

### Navigation (`src/navigation/RootNavigator.tsx`)
- **Signed out:** an auth stack with Phone, then OTP.
- **Signed in:** a bottom tab bar with 5 tabs:
  - **Home**: a stack of HomeMain and Offers.
  - **Refer**
  - **Leads**: a stack of Leads, LeadDetail and NewLead (NewLead opens as a modal).
  - **Earnings**
  - **Profile**: a stack of Profile and KYC.
- On entering the tabs, `registerForPush()` runs. It does nothing inside Expo Go or on an emulator.
- The session token lives in `expo-secure-store` (`src/store/auth.ts`). Any 401 from a non-`/auth` call signs the user
  out locally (`src/api/client.ts`).

### Phone screen — `screens/auth/PhoneScreen.tsx`
| Element | Action |
|---|---|
| Mobile number field | Digits only, 10 max; must match `^[6-9]\d{9}$` to enable the button |
| **Get OTP** | → `POST /auth/otp/send`, then navigates to the OTP screen. Errors such as the 30 s cooldown or lockout appear in a red banner. |

### OTP screen — `screens/auth/OtpScreen.tsx`
| Element | Action |
|---|---|
| OTP field | Digits, 6 max; the button enables at 4+ digits (the dev OTP is 1234) |
| Your name (new users) | Optional; sent as `name` |
| **Have a referral code?** (link) | Shows the referral code field. Once 6+ characters are typed, it waits 400 ms, calls `GET /referrals/code/:code`, and shows "Invited by …" |
| **Verify & continue** | → `POST /auth/otp/verify`; on success stores the token and user, and the tab navigator appears. Errors (wrong OTP, lockout, admin account) appear in the banner. |
| **Resend OTP** | Disabled for 30 s (with a countdown); → `POST /auth/otp/send` |

### Home — `screens/HomeScreen.tsx`
Loads `GET /earnings/summary`, `GET /leads/stats` and `GET /offers` together.
| Element | Action |
|---|---|
| Balance card | Shows "Available to withdraw" (ledger balance), "Pending approval" and "Total earned". Display only. |
| **Complete your KYC** card (only while KYC isn't verified) | Tap → Profile tab |
| **Earn with Refera** section (only when there are offers) | Shows up to 2 **direct** offers in compact form (tier 1 only). Tapping a card → Offers screen. **See all N offers** → Offers screen. |
| "Your leads" grid | 5 status counts. Display only. |
| **Add a lead** | → Leads tab → NewLead (default product: loan) |
| **Share link** | → Refer tab |

### Offers — `screens/OffersScreen.tsx` + `components/OfferCard.tsx`
Loads `GET /offers`.
| Element | Action |
|---|---|
| Product chips (**All**, then one per product that has offers; only shown when more than one product has offers) | Filter the cards locally |
| Section "Refer & earn" | Cards for tier-1 rules |
| Section "Team bonuses" | Cards for tier ≥ 2 rules, with a dashed card style |
| Card content | Product badge; "Direct referral", "Team bonus" or "Team bonus · level n"; title (admin-written, or generated by `offerTitle()`); amount + basis (e.g. "₹1,500 per approved card", "1% of the loan amount"); description (admin-written, or generated) |
| **Add a lead** (direct cards) | → Leads tab → NewLead **with that product preselected** (`params.productType`) |
| **Invite to your team** (team cards) | → Refer tab |

### Refer — `screens/ReferralsScreen.tsx`
Loads `GET /referrals/link` and `GET /referrals/downline?depth=3`.
| Element | Action |
|---|---|
| Code box + link text | Display |
| **Share** | Opens the native share sheet with a message containing the code and URL |
| **Copy code** | Copies the code to the clipboard; the label shows "Copied!" for 1.5 s |
| "Your team" counts line | e.g. "Level 1: 2 · Level 2: 1" |
| Team list | Each member shows name (or phone), level, join date, lead count and a KYC badge. Phone is masked for level ≥ 2. No actions. |

### Leads — `screens/leads/LeadsScreen.tsx`
| Element | Action |
|---|---|
| Search field | Debounced 350 ms → `GET /leads?search=` |
| Status chips (All, New, Contacted, In progress, Converted, Rejected) | → `GET /leads?status=` |
| Lead row | → LeadDetail |
| Scroll to the end | Loads the next page (infinite scroll) |
| **+ Add lead** (floating) | → NewLead |

### New lead — `screens/leads/NewLeadScreen.tsx`
| Element | Action |
|---|---|
| Product chips (Loan, Credit card, Insurance) | Pick the product (preselected when opened from an offer) |
| Customer name, Customer mobile | Required (name 2+ characters, a valid 10-digit mobile) |
| Amount field (label depends on product) | Optional estimate in ₹ (**informational only**: commissions use the admin's confirmed amount) |
| Notes | Optional |
| **Submit lead** | → `POST /leads`, then replaces the screen with the new lead's detail. Duplicate open leads get an error. |

### Lead detail — `screens/leads/LeadDetailScreen.tsx`
Loads `GET /leads/:id`.
| Element | Action |
|---|---|
| Header, phone, deal amount, created and updated dates, notes | Display |
| **Call lead** | Opens the phone dialler (`tel:`) |
| Progress list | Shows how far along new → contacted → in progress → converted the lead is, or "not converted" if rejected |
| "Your commission" card (only when present) | Tier, amount and status badge per commission row belonging to you |

### Earnings — `screens/EarningsScreen.tsx`
Loads `GET /earnings/summary`, `/earnings/ledger`, `/earnings/commissions` and `/earnings/payouts` (first page of each).
| Element | Action |
|---|---|
| Balance card | Available balance, plus Pending, Paid out and In process |
| **Withdraw** | Disabled while the balance is below the minimum. If KYC isn't verified, an alert says "KYC required". Otherwise it opens the Withdraw sheet. |
| Chips **History** / **Commissions** / **Payouts** | Switch the list to ledger entries, commissions (lead, product, tier, status) or payouts (amount, status, UTR or failure reason) |
| Withdraw sheet: Amount field | ₹, between the minimum and the available balance |
| Withdraw sheet: **Request payout** | → `POST /earnings/payouts`; on success, an alert and a reload |
| Withdraw sheet: **Cancel** | Closes the sheet |

### Profile — `screens/profile/ProfileScreen.tsx`
Loads `GET /me` and refreshes the cached user.
| Element | Action |
|---|---|
| **Edit profile** | Switches to edit mode with Name and Email fields |
| **Save** / **Cancel** (edit mode) | → `PATCH /me` / leave edit mode |
| KYC card: **Continue KYC** or **View KYC details** | → KYC screen |
| **Log out** | Asks for confirmation, then → `POST /auth/logout` (best effort), then clears the local session |
| Footer | Shows the API URL the app is using |

### KYC — `screens/profile/KycScreen.tsx`
Loads `GET /kyc`. While the status is pending or verified, steps 1–3 show only their result, with no inputs.
| Step / element | Action |
|---|---|
| Status card | Badge; shows "under review" text, or the rejection reason |
| 1 Aadhaar: Aadhaar number + **Send OTP** | → `POST /kyc/aadhaar/otp` (the number is cleared from the screen afterwards) |
| 1 Aadhaar: OTP + **Verify** | → `POST /kyc/aadhaar/verify` (5 wrong guesses, then a new OTP is needed) |
| 1 Aadhaar: **Change Aadhaar number** | Back to number entry |
| 2 PAN: PAN + Name as on PAN + **Verify PAN** | → `POST /kyc/pan` |
| 3 Bank: Account, Confirm account, IFSC + **Verify bank account** | → `POST /kyc/bank` (the button stays disabled until both account entries match) |
| 4 Documents: document row | Opens the document's signed URL |
| 4 Documents: **Upload PAN card** / **Bank proof** | Document picker (JPG, PNG, PDF; ≤ 5 MB checked on the device) → `POST /kyc/documents`. Hidden once KYC is verified. |
| After each successful step | Refreshes `GET /me` so Home and Earnings see the new KYC status |

## Admin panel (`services/admin-dashboard`)

### Shell — `src/App.tsx`, `src/auth.tsx`
- Shows the Login page when no valid admin token is stored. On load, it calls `GET /me` and discards any token that
  doesn't belong to an admin.
- Sidebar links: **Overview** `/`, **Lead queue** `/leads`, **KYC review** `/kyc`, **Commissions** `/commissions`,
  **Payouts** `/payouts`, **Commission rules** `/rules`, **Affiliates** `/users`.
- **Sign out** → `POST /auth/logout` (best effort), then clears the token from `localStorage`.
- Any 401 on a non-`/auth` call signs out locally.

### Login — `pages/LoginPage.tsx`
Email and password → **Sign in** → `POST /auth/admin/login`.

### Overview — `pages/DashboardPage.tsx`
Calls `GET /admin/analytics`.
- 6 stat cards: Affiliates (+30 days), KYC verified, Total leads, Commissions pending, Commissions approved, Paid out.
- Three of them have links: "N awaiting review" → `/kyc`, "Review" → `/commissions`, "N payouts open" → `/payouts`.
- "Leads by status" bar list and a 30-day signups bar chart. Both are display only.

### Lead queue — `pages/LeadsPage.tsx`
Calls `GET /leads` (admin view, 25 per page).
| Element | Action |
|---|---|
| Search box | Filters by name or phone |
| Tabs New, Contacted, In progress, Converted, Rejected, All | Status filter (default: New) |
| Row buttons: **→ Contacted**, **→ In progress** | → `PATCH /admin/leads/:id/status` |
| Row button **Reject** | Confirm dialog → PATCH `status: rejected` |
| Row button **→ Converted** | Opens the Convert dialog |
| Convert dialog: final deal amount (₹, **not pre-filled**; the affiliate's estimate is shown as a hint), Notes, **Mark converted**, **Cancel** | → PATCH `{status: 'converted', dealAmount, notes}`. The server refuses if a percentage rule applies and no amount is given. |
| Pager | Prev and Next |

### KYC review — `pages/KycPage.tsx`
Calls `GET /admin/kyc?status=`.
| Element | Action |
|---|---|
| Tabs: Awaiting review (pending), In progress (unverified), Verified, Rejected | Filter the queue |
| Row: Aadhaar, PAN and bank check marks (masked PAN and account), doc count, updated date; **Review** | Opens the detail modal → `GET /admin/kyc/:userId` |
| Modal | Shows phone, name per Aadhaar, checks, masked PAN, masked account + IFSC, last rejection, and document links (signed URLs, open in a new tab) |
| Modal (pending only): rejection reason field + **Reject** | → `POST /admin/kyc/:userId/reject` (reason of 3+ characters required) |
| Modal (pending only): **Approve KYC** | → `POST /admin/kyc/:userId/approve` |
| **Close** | Closes the modal |

### Commissions — `pages/CommissionsPage.tsx`
Calls `GET /admin/commissions?status=`.
| Element | Action |
|---|---|
| Tabs: Pending approval, Approved, Paid, Rejected | Filter |
| Row: affiliate, lead + product, tier (Direct / Level n), deal amount, commission amount, status, date | Display |
| **Approve** (pending only) | → `POST /admin/commissions/:id/approve` (credits the ledger) |
| **Reject** (pending only) | Confirm dialog → `POST /admin/commissions/:id/reject` |

### Payouts — `pages/PayoutsPage.tsx`
Calls `GET /admin/payouts?status=`.
| Element | Action |
|---|---|
| Tabs: Requested (pending), Processing, Completed, Failed | Filter |
| Row: affiliate, masked bank account + IFSC, amount, status, reference or failure reason, date | Display |
| **Start processing** (pending) | → `POST /admin/payouts/:id/process` |
| **Mark paid** (pending or processing) | Browser prompt for the UTR → `POST /admin/payouts/:id/complete` |
| **Fail** (pending or processing) | Browser prompt for a reason → `POST /admin/payouts/:id/fail` (refunds the balance) |

### Commission rules & offers — `pages/RulesPage.tsx`
Calls `GET /admin/commission-rules`.
| Element | Action |
|---|---|
| "New rule" form: Product, Type (% of deal / Flat ₹), Amount or Percent, Tier, **Offer title** (≤ 80), **Description** (≤ 500, with a live counter), **Add rule** | → `POST /admin/commission-rules`. After adding, the form clears but keeps the product and type. |
| Table columns: Offer (title and 2-line description, or "No title (the app shows a generated one)"), Product, Tier, Payout, Status | Display |
| **Edit** | Opens the Edit dialog: the same fields, with **product locked**, then **Save** → `PATCH /admin/commission-rules/:id` (type, value, tier, title, description), or **Cancel** |
| **Pause** / **Activate** | → PATCH `{active}`. Paused rules stop paying and disappear from the app's offers. |
| **Delete** | Confirm dialog → `DELETE /admin/commission-rules/:id` (existing commissions keep their amounts; their `ruleId` becomes null) |

### Affiliates — `pages/UsersPage.tsx`
Calls `GET /admin/users?role=affiliate`. Read-only.
| Element | Action |
|---|---|
| KYC state dropdown, search box | Filters |
| Row: name, phone, email, invited by, lead count, team size, KYC badge, join date | Display only. There is no user detail page, even though `GET /admin/users/:id` exists. |
| Pager | Prev and Next |
